# Expose Configured MCP Tools through the Tool Gateway

User Configuration may define trusted MCP Servers using stdio or Streamable HTTP, with exactly one `[mcp.servers.<mcp_name>]` item for each Server and no configurable process environment. A stdio Server inherits the MyClaw process environment unchanged; a Streamable HTTP Server may declare static headers in its Server item. Whole-document TOML syntax errors retain the existing fatal configuration behavior, while an invalid MCP Server item is omitted independently and reported by startup, `myclaw config`, and `/config` through sanitized diagnostics. The default configuration contains commented stdio and Streamable HTTP examples but enables no Server. The CLI owns Python MCP SDK v2 clients for the Runtime Lifetime, connects valid enabled Servers concurrently before the initial Agent Loop starts, and concurrently retries unavailable Servers while preparing a later Runtime Generation; each connection has independent initialization and call timeouts. Each generation receives an immutable MCP Tool Snapshot containing only successfully discovered Tools, with no live list subscription or MCP reload command. An invalid Server item or failed connection is logged without configuration content, reported as a brief sanitized terminal line, and omitted without blocking startup.

Each MCP Tool is a `BaseTool` and enters the same Tool Catalog, model-request `tools` field, final preparation pipeline, execution boundary, result externalization, and Tool Result normalization as a Built-in Tool. Every Tool exposes `name`, `description`, and model-facing `parameters: dict[str, Any]`; `to_schema()` performs a pure projection, and the complete `tools: list[dict[str, Any]]` request argument is rebuilt by calling every available Tool on each Model request rather than cached by the Tool or Tool Gateway. A Built-in Tool reconstructs a temporary `Schema` from its declaration for each invocation so its existing casting, defaults, field filtering, and validation remain unchanged without retaining that Schema. An MCP Tool retains its discovered JSON Schema after recursive OpenAI-compatible `nullable` normalization and forwards the complete `dict[str, Any]` without local validation, casting, or removal of additional fields. Missing MCP Tool descriptions use the original remote Tool name. Tool-specific descriptions are not added to the System Prompt, and the Tool boundary does not retain the `JsonObject` alias or `PreparedToolCall` type.

`BaseTool.prepare()` remains final and returns `(dict[str, Any], str | None)` after delegating argument preparation, Tool-specific validation, and safety checking through polymorphic hooks. `ToolGateway` invokes every prepared Tool through `execute_prepared(arguments: dict[str, Any])`; the default implementation expands Built-in Tool keyword arguments, while `MCPTool` overrides the method to call the remote Tool with the complete dictionary. The Gateway does not branch on Tool origin.

The Tool module and its direct interfaces use `dict[str, Any]` rather than the existing JSON aliases and typed OpenAI Tool dictionaries; unrelated JSON boundaries are unchanged. A concrete `BaseTool` must override at least one execution method: Built-in Tools retain `execute()`, while `MCPTool` implements only `execute_prepared()`.

Configured MCP Tools are trusted capabilities that execute without Tool Confirmation in foreground and User Schedule Agent Runs, while Dream keeps its restricted Tool Catalog. The first implementation supports paginated Tool discovery and immediately completed Tool calls only, performs no automatic call retry, skips unusable Servers or individual Tools, and maps only `CallToolResult.content` to the existing text-only Tool boundary. Tool call timeouts and Tool execution errors become `ToolError` results without marking the MCP Server unavailable; only an SDK-confirmed closed session or transport marks it for reconnection during a later Runtime Generation, without mutating the current generation's Tool Catalog. Runtime status does not expose MCP information.

Tool cancellation follows the Built-in Tool contract and propagates unchanged. Runtime shutdown first stops and drains Agent Runs, then closes MCP clients before Dream and the Model Router. A connected Server with skipped Tools produces one aggregate terminal notice and per-Tool process-log records.

Every context-budget decision measures the complete content of the corresponding Model request: System Prompt, all messages, and every Tool schema. Compression trigger and cutoff calculations therefore reserve the complete Tool schema cost, and startup or `/resume` preflight uses the complete generation Tool Catalog. All local and Provider context-overflow paths use the single stable `model_context_overflow` code, and local budget failures use the single message `Model request context exceeds the available input budget.`

This decision supersedes the fixed-ten-Tool and no-MCP portions of ADR-0010 while retaining its Tool Gateway, Built-in Tool, confirmation, result, and artifact boundaries where this ADR does not say otherwise.
