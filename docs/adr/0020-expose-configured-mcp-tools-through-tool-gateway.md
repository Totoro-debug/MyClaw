# Expose Configured MCP Tools through the Tool Gateway

The approved implementation uses the official MCP Python SDK v2 with the package constraint
`mcp>=2,<3` and the `streamable-http` transport name. MCP Tool invocation uses the SDK
`call_tool` operation; `structured_content` and `outputSchema` are outside the accepted result
projection.

User Configuration may define MCP Servers selected by the user through stdio or Streamable HTTP, with exactly one `[mcp.servers.<mcp_name>]` item for each Server and no configurable process environment. A stdio Server inherits the MyClaw process environment unchanged; a Streamable HTTP Server may declare static headers in its Server item. Whole-document TOML syntax errors retain the existing fatal configuration behavior, while an invalid MCP Server item is omitted independently and reported by startup, `myclaw config`, and `/config` through sanitized diagnostics. The default configuration contains commented stdio and Streamable HTTP examples but enables no Server. The CLI owns Python MCP SDK v2 clients for the Runtime Lifetime, connects valid enabled Servers concurrently before the initial Agent Loop starts, and concurrently retries unavailable Servers while preparing a later Runtime Generation; each connection has independent initialization and call timeouts. Each generation receives an immutable MCP Tool Snapshot containing only successfully discovered Tools, with no live list subscription or MCP reload command. An invalid Server item or failed connection is logged without configuration content, reported as a brief sanitized terminal line, and omitted without blocking startup.

Each MCP Tool is a `BaseTool` and enters the Runtime Generation Tool Catalog, final preparation pipeline, execution boundary, result externalization, and Tool Result normalization as a Built-in Tool. It remains directly callable through any Agent Run Tool Catalog that contains it, while its complete invocation definition enters a model request's `tools` field only when exposed for that request. Every Tool exposes `name`, `description`, and model-facing `parameters: dict[str, Any]`; `to_schema()` performs a pure projection, and the complete `tools: list[dict[str, Any]]` request argument is rebuilt from the Tools exposed for each Model request rather than cached by the Tool or Tool Gateway. [ADR-0021](0021-defer-tool-schema-exposure-per-agent-run.md) defines deferred schema exposure and Agent Run-scoped activation. A Built-in Tool reconstructs a temporary `Schema` from its declaration for each invocation so its existing casting, defaults, field filtering, and validation remain unchanged without retaining that Schema. An MCP Tool retains its discovered JSON Schema after recursive OpenAI-compatible `nullable` normalization and forwards the complete `dict[str, Any]` without local validation, casting, or removal of additional fields. Missing MCP Tool descriptions use the original remote Tool name. Tool-specific descriptions are not added to the System Prompt, and the Tool boundary does not retain the `JsonObject` alias or `PreparedToolCall` type.

`BaseTool.prepare()` remains final and returns `(dict[str, Any], str | None)` after delegating argument preparation, Tool-specific validation, and safety checking through polymorphic hooks. `ToolGateway` invokes every prepared Tool through `execute_prepared(arguments: dict[str, Any])`; the default implementation expands Built-in Tool keyword arguments, while `MCPTool` overrides the method to call the remote Tool with the complete dictionary. The Gateway does not branch on Tool origin.

The Tool module and its direct interfaces use `dict[str, Any]` rather than the existing JSON aliases and typed OpenAI Tool dictionaries; unrelated JSON boundaries are unchanged. A concrete `BaseTool` must override at least one execution method: Built-in Tools retain `execute()`, while `MCPTool` implements only `execute_prepared()`.

Configured MCP Tools are external capabilities in the Runtime Generation Tool Catalog. In a foreground Agent Run, Read-Only and Workspace-Write require one exact-call Tool Confirmation for every normalized MCP invocation; Full-Access executes directly. The confirmation carries the stable server name, remote Tool name, projected model Tool name, and the complete normalized argument object, and is discarded with that call rather than becoming a Server, Tool, argument, Host, or connection grant. User Schedule Agent Runs use their admission permission snapshot through the run-local Gateway: Read-Only and Workspace-Write submit each exact call to the shared background confirmation coordinator, while Full-Access executes directly. Dream does not expose MCP Tools and follows [ADR-0024](0024-use-one-shot-dream-model-request.md) by exposing and executing only `edit_file` in its one-shot request. The first implementation supports paginated Tool discovery and immediately completed Tool calls only, performs no automatic call retry, skips unusable Servers or individual Tools, and maps only `CallToolResult.content` to the existing text-only Tool boundary. Tool call timeouts and Tool execution errors become `ToolError` results without marking the MCP Server unavailable; only an SDK-confirmed closed session or transport marks it for reconnection during a later Runtime Generation, without mutating the current generation's Tool Catalog. Runtime status does not expose MCP information.

Tool cancellation follows the Built-in Tool contract and propagates unchanged. Runtime shutdown first stops and drains Agent Runs, then closes MCP clients before Dream and the Model Router. A connected Server with skipped Tools produces one aggregate terminal notice and per-Tool process-log records.

Overall Projected Next-request Usage, its soft compression trigger, the hard Available Context check, and startup or `/resume` preflight measure the complete corresponding Model request: System Prompt, all messages, and every Tool schema exposed in that request. The separate 10% and 50% retention slices defined by [ADR-0023](0023-manage-agent-run-context-by-projected-token-budget.md) deliberately exclude Tool schemas and every other non-target-Agent-Run input. Exposure selection follows [ADR-0021](0021-defer-tool-schema-exposure-per-agent-run.md); an activation changes the request revision and is checked before the next ReAct request. All local and Provider context-overflow paths use the single stable `model_context_overflow` code, and local budget failures use the single message `Model request context exceeds the available input budget.`

MCP names use `mcp_<mcp_name>_<remote_name>`, falling back to `mcp_<remote_name>` only if the preferred name exceeds 64 characters. The selected name must match `[A-Za-z0-9_-]{1,64}` without truncation or character replacement. Built-in names are reserved. Servers are ordered by name, and remote Tools by remote name with deterministic definition tie-breakers; the first valid collision wins. The resulting MCP Tools follow the Built-in Tools in the Runtime Generation Tool Catalog.

Nullable normalization traverses JSON Schema nodes only. It preserves property names and literal data under keywords such as `default`, `enum`, and `examples`, including data keys named `nullable`. It does not recursively rewrite arbitrary JSON objects as schemas. MCP `isError` results retain projected remote text as Tool Error content; sanitized configuration and connection diagnostics do not imply sanitization of model-visible Tool Results.

The shared Built-in Tool and result boundaries follow [ADR-0010](0010-fixed-tool-catalog-and-base-tool-boundaries.md). Requirements: [MCP Tool support](https://github.com/Totoro-debug/myclaw/issues/217).
